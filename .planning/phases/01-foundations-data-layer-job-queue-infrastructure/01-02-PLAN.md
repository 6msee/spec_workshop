<objective>
Extend the walking skeleton's proven path one layer further: the ticket that plan 01-01 persists now
also enqueues a background job, and a separate worker process claims that job atomically, runs it
through an idempotency seam, and marks it complete.

**User story (MVP):** **As** the UP-Fix system, **I want to** hand every accepted fault report to a
background worker that is guaranteed to process it exactly once, **so that** intake stays fast and no
report is ever processed twice or lost when a worker crashes.

Purpose: this is the queue Phase 2's AI pipeline enqueues into. Phase 1 proves the mechanics — atomic
claim, bounded retries, stale-lock recovery, and the idempotency contract — against a no-op handler, so
Phase 2 inherits correctness rather than re-litigating it while also debugging prompts. Per D-04 a
single always-restarting worker ships; the claim SQL is already multi-worker-safe, so scaling out later
is a deployment change with no code change. Per D-03 the supervisor config targets Linux/systemd first.

Output: the `job_queue` table, `JobQueue`/`Dispatcher`/`HandlerInterface`/`NoopHandler`, `bin/worker.php`,
`bin/scheduler.php`, the systemd unit and cron entry, and concurrency tests that prove no
double-processing.
</objective>

    `dispatch(array $job): void` which: decodes `payload` with
