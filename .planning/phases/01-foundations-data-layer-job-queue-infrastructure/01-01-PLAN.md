<objective>
Stand up the UP-Fix walking skeleton: the thinnest production-quality path that carries a reporter's
text through the HTTP front controller, the router, a controller, a race-safe ticket-number allocator,
and into SQL Server — returning a real `UPF-YYYYMM-NNNNN` ticket number and leaving behind an
append-only audit event that the application's own database login is powerless to edit.

**User story (MVP):** **As a** member of the Division of Buildings and Grounds, **I want to** submit a
fault report to the UP-Fix intake API and get back a permanent ticket number, **so that** the fault is
recorded in one authoritative place with a tamper-proof history from the very first event.

Purpose: every later phase (AI classification, routing, LINE, dashboard) writes through these exact
seams. `Connection.php`'s deadlock retry, `EventLog.php`'s single audit write path, and
`bin/migrate.php`'s ordering contract are inherited, not re-decided. AUDIT-01 — the phase's only mapped
requirement — is made true here at the database-privilege level (per D-01, migrations carry paired
`_up.sql`/`_down.sql` files).

Output: a runnable PHP application skeleton, five applied migrations, a working `POST /api/v1/tickets`,
and automated tests proving the audit table cannot be rewritten.
</objective>
